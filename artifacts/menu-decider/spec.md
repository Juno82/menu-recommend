# Menu Decider — Spec

## 개요
사용자의 현재 위치·날씨·시간대와 선택적 자유 프롬프트를 합성해 *오늘 먹을 메뉴 1개*를 결정해주고, 같은 화면 하단에 그 메뉴를 파는 것으로 추정되는 근처 식당 Top3와 지도를 부착해 행동까지 연결한다.

## 범위

### 포함
- 단일 페이지(라우트 하나)에서 입력 → 결정 → 식당 부착 흐름
- 위치 자동 조회(브라우저 Geolocation), 거부 시 수동 지역 입력 fallback
- 위치 기반 날씨 자동 조회 + 시간대 자동 판정
- 자유 프롬프트 입력(선택적, 비워도 추천 가능)
- 메뉴 카드 1장(메뉴명 + 한 줄 추천 이유)
- 근처 식당 Top3 + 지도(핀 3개)
- 식당별 추정 대표 메뉴 1-3개 + 추정 가격대(LLM 생성, 항상 disclaimer 동반)
- "다시 추천" — 같은 세션에서 이전 메뉴 제외 보장
- 한국어 UI, 한국 국내 위치/식당 대상
- 데스크톱·모바일 둘 다 지원

### 제외
- 로그인·계정·이력 — Must Be True 가정 검증 전에는 무가치 (idea.md 결정)
- 실제 메뉴 사진 — 신뢰할 만한 소스 없음, 텍스트 only
- 영양/알레르기 필터 — 다른 문제 도메인. 자유 프롬프트로 우회 가능
- 모바일 네이티브 앱 — 웹 단일 페이지로 검증 충분

## 시나리오

### 1. 위치 허용 + 프롬프트 입력 → 정상 추천
- **Given** — 사용자가 페이지에 진입해 브라우저 위치 권한을 허용한 상태, 자유 프롬프트 입력 칸에 "느끼한 거 빼고"를 입력함
- **When** — "추천받기" 버튼을 클릭
- **Then** — 3초 이내에 메뉴 카드 1장(메뉴명과 한 줄 이유)이 화면에 나타나고, 이어서 근처 식당 카드 3개와 지도(핀 3개)가 채워진다

성공 기준:
- [ ] "추천받기" 클릭 후 3초 이내에 메뉴명과 한 줄 이유가 포함된 카드 1개가 화면에 표시된다
- [ ] 메뉴 카드 표시 이후, 같은 화면에 식당 카드 3개와 지도가 채워진다
- [ ] 메뉴 카드가 식당 카드보다 먼저 화면에 나타난다
- [ ] 각 식당 카드에 식당명, 도보 거리, 추정 대표 메뉴 1-3개, 추정 가격대, 카카오맵 상세 외부 링크가 표시된다
- [ ] 지도에는 식당 위치를 가리키는 핀 3개가 표시된다

### 2. 빈 프롬프트로 추천
- **Given** — 위치 권한이 허용된 상태, 자유 프롬프트 칸이 비어 있음
- **When** — "추천받기" 버튼을 클릭
- **Then** — 에러 없이 메뉴 카드 1장 → 식당 Top3 + 지도 흐름이 시나리오 1과 동일하게 진행된다

성공 기준:
- [ ] 빈 프롬프트 + "추천받기" → 입력 유효성 에러 메시지 없이 메뉴 카드가 표시된다
- [ ] 프롬프트 칸은 빈 채로 유지되며 placeholder 예시 텍스트만 시각적으로 보인다
- [ ] 메뉴 카드의 한 줄 이유에 날씨·시간대 단서가 자연어로 포함된다 (예: "비 오는 오후라면 따끈한 칼국수")

### 3. 위치 권한 거부 → 수동 지역 입력
- **Given** — 사용자가 페이지에 진입해 브라우저 위치 권한을 거부한 상태
- **When** — 페이지의 지역 입력 칸에 "강남역"을 입력하고 "추천받기" 버튼을 클릭
- **Then** — 입력 지역 좌표를 기준으로 시나리오 1과 동일한 결과가 표시된다

성공 기준:
- [ ] 위치 권한 거부 상태에서는 지역명 텍스트 입력 칸과 "위치 정보를 사용할 수 없어요. 지역을 입력해 주세요" 안내가 표시된다
- [ ] 유효한 지역명 입력 → 그 지역 좌표 기준 식당 Top3와 지도가 표시된다
- [ ] 인식 불가한 지역명 입력 + "추천받기" → "지역을 찾을 수 없습니다. 다시 입력해 주세요" 메시지가 입력 칸 아래에 표시된다

### 4. 식당 검색 결과 없음 (0개 또는 식당 API 실패)
- **Given** — 메뉴는 정상적으로 결정되었으나, 카카오 로컬 API 검색 결과가 0개이거나 API 호출이 실패한 상태
- **When** — 메뉴 카드 표시 후 시스템이 식당 영역을 채우려 시도
- **Then** — 메뉴 카드는 그대로 유지되고, 식당 영역에는 카카오맵 외부 링크 하나만 fallback으로 표시된다

성공 기준:
- [ ] 검색 결과 0개/실패 시 메뉴 카드 영역은 변경되지 않고 표시 상태로 유지된다
- [ ] 식당 영역에 "근처 식당을 찾지 못했습니다. 카카오맵에서 직접 검색 →" 텍스트와 외부 링크가 표시된다
- [ ] 외부 링크는 `https://map.kakao.com/?q={메뉴명}` 형태로 새 탭에서 열린다
- [ ] 식당 카드 3개 자리와 지도는 표시되지 않는다

### 5. "다시 추천" — 같은 세션에서 다른 메뉴 보장
- **Given** — 사용자가 이미 한 번 추천을 받아 메뉴 카드("칼국수")가 화면에 표시된 상태
- **When** — 입력 변경 없이 "다시 추천" 버튼을 클릭
- **Then** — 3초 이내에 이전과 다른 메뉴명이 표시된 카드로 교체되고, 식당 영역이 새 메뉴 기준으로 다시 채워진다

성공 기준:
- [ ] "다시 추천" 클릭 후 3초 이내 새 메뉴 카드가 화면에 표시된다
- [ ] 새 메뉴 카드의 메뉴명은 같은 세션에서 이미 표시되었던 메뉴명들과 다르다
- [ ] 식당 Top3 영역이 새 메뉴 기준으로 다시 채워진다 (또는 시나리오 4에 따라 fallback)

### 6. LLM 호출 실패 → 에러 + 재시도
- **Given** — 사용자가 "추천받기"를 눌렀으나 LLM API 호출이 실패한 상태 (네트워크/타임아웃/한도 초과 등)
- **When** — 시스템이 실패를 인지
- **Then** — 명시적 에러 메시지와 "다시 시도" 버튼이 표시되고, 빈/잘못된 카드 등 부분 결과는 표시되지 않는다

성공 기준:
- [ ] LLM 호출 실패 → "추천을 불러오지 못했습니다. 잠시 후 다시 시도해 주세요" 메시지와 "다시 시도" 버튼이 표시된다
- [ ] 실패 상태에서 메뉴 카드/식당 카드/지도는 표시되지 않는다
- [ ] "다시 시도" 버튼 클릭 → 이전 입력값(프롬프트, 위치)을 유지한 채로 추천 흐름이 재개된다

## 불변 규칙

### 응답 시간
- 사용자가 "추천받기" 또는 "다시 추천"을 누른 시점부터 메뉴 카드 1장이 화면에 텍스트로 표시되기까지 3초 이내.

### 결과 순서
- 모든 정상 추천 흐름에서 메뉴 카드가 식당 카드보다 먼저 화면에 나타난다 — 메뉴 결정 가치를 식당 데이터 지연이 가리지 않도록.

### Hallucination 투명성
- 식당 카드에 추정 메뉴와 추정 가격이 표시되는 모든 곳에는 "메뉴·가격은 AI 추정값입니다. 실제는 가게에서 확인해 주세요" 안내 텍스트가 함께 보인다. 이 텍스트는 식당 카드 하단에 항상 보이며 사용자가 닫을 수 없다.

### 위치 데이터 처리
- Geolocation으로 얻은 좌표 또는 수동 입력 지역명은 같은 페이지 세션 동안만 메모리에 유지되고, 페이지 이탈/새로고침 시 폐기된다. 서버에 저장되지 않는다.

## 의존성
- 외부 시스템: 카카오 로컬 검색 API, 카카오맵 지도, Open-Meteo 날씨 API, LLM API
- 사용자 브라우저: Geolocation API 지원 또는 수동 지역 입력 UI 둘 중 하나 작동 가능

## 미결정 항목
- 식당 카드/지도가 화면에 채워지기까지의 인내선 정량 임계값 — 메뉴 카드는 3초 이내로 확정, 식당 영역은 "메뉴 카드 이후 도착"으로만 보장. 정량 기준은 첫 구현 측정 후 결정
